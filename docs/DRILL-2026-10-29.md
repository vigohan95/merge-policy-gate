## What this proves and what it does not

- The policy file is read from the destination branch (`main`), so PR #2 could not loosen its own rules.
- Dependency classification worked on a real `requirements.txt` diff between destination and source commits.
- Not yet exercised: `§3.6` release by a reviewer approval (needs a second user in the workspace; a self-approval does
  not count), `§3.4` size limits on a real diff, the `on-merge` trigger, the Rovo agent (cannot run in this app, see
  below) and the MCP tools.

## Platform limit found

`forge install --product jira` fails with "Workspace scopes can not be used with site scopes": one Forge app cannot
hold Bitbucket workspace scopes and Jira site scopes. Consequences: the Jira status rule was reduced to key presence,
and the Rovo agent must live in a second, Jira-scoped app that reads verdicts from this app over a web trigger.
